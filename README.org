* Overview
:PROPERTIES:
:CUSTOM_ID: overview
:END:

=sprite-mcp= spawns isolated [[https://github.com/tychoish/sprite][sprite]] sub-daemons, each rooted in its own linked git worktree under =<repo-root>/.wt/<id>= so that concurrent sprites never share (and stomp on) a working tree. Inside each daemon it loads [[https://github.com/tychoish/mcpkit.el][mcpkit]], starts an MCP service on a freshly allocated local port, and registers =mcpkit-editing='s core editing/diagnostics tools (=mcp_buffer_read=, =mcp_buffer_replace_region=, =mcp_ast_grep=, =mcp_project_diagnostics=) on that service. It then registers a reverse-proxy route for the sprite's opaque id with =mcpkit-proxy=, so the proxy gateway can forward MCP traffic to that sprite without callers needing to track individual ports. =sprite-mcp-kill= tears all of this back down, and an idle reaper periodically kills sprites whose last contact (tracked by sprite.el itself) has gone stale.

* Installation
:PROPERTIES:
:CUSTOM_ID: installation
:END:

=sprite-mcp= is not yet published on MELPA or ELPAish; install it directly from its Git repository. Its dependency =sprite= is distributed via ELPAish -- see [[https://github.com/tychoish/sprite#elpaish-recommended][sprite's installation instructions]] for archive and keyring setup before installing =sprite-mcp=. =mcpkit=, =mcpkit-editing=, and =mcpkit-proxy= are only ever loaded inside the spawned sprite daemons themselves (and, for =mcpkit-proxy=, on the parent side to register/unregister routes); see [[https://github.com/tychoish/mcpkit.el#elpaish-recommended][mcpkit.el's installation instructions]] for making them available on the sprites' =load-path=.

** use-package with VC
:PROPERTIES:
:CUSTOM_ID: use-package-with-vc
:END:
Requires Emacs 29.1+. Installs on first load if not already present:

#+BEGIN_SRC emacs-lisp
(use-package sprite-mcp
  :vc (:url "https://github.com/tychoish/sprite-mcp")
  :after sprite)
#+END_SRC

** Manual Installation
:PROPERTIES:
:CUSTOM_ID: manual-installation
:END:
#+BEGIN_SRC sh
git clone https://github.com/tychoish/sprite-mcp ~/.emacs.d/site-lisp/sprite-mcp
#+END_SRC

#+BEGIN_SRC emacs-lisp
(add-to-list 'load-path "~/.emacs.d/site-lisp/sprite-mcp")
(require 'sprite-mcp)
#+END_SRC

With Emacs 29.1+, you can also use ~package-vc-install~:

#+BEGIN_SRC emacs-lisp
(package-vc-install '(sprite-mcp
                      :url "https://github.com/tychoish/sprite-mcp"))
#+END_SRC

* Usage
:PROPERTIES:
:CUSTOM_ID: usage
:END:

Spawn a sprite daemon hosting an MCP service rooted in a fresh worktree of the current repository:

#+BEGIN_SRC emacs-lisp
(sprite-mcp-start-idle-reaper) ;; once, to reap sprites idle past `sprite-mcp-idle-timeout'

(defvar my/demo-sprite
  (sprite-mcp-spawn :name "demo" :repo-root (project-root (project-current))))
#+END_SRC

This creates a linked git worktree, spawns the sprite daemon, starts an mcpkit MCP service inside it on an allocated port, registers =mcpkit-editing='s tools on that service, and registers a =mcpkit-proxy= route for the sprite's id, so MCP clients can reach it through the proxy gateway without knowing its port directly.

Tear it down explicitly when done, or let the idle reaper reap it once it goes quiet past =sprite-mcp-idle-timeout= (30 minutes by default):

#+BEGIN_SRC emacs-lisp
(sprite-mcp-kill my/demo-sprite)
#+END_SRC

* Plain sprite tools (sprite-mcp-tools)
:PROPERTIES:
:CUSTOM_ID: sprite-mcp-tools
:END:

=sprite-mcp-tools.el= is separate from =sprite-mcp-spawn=: it registers MCP tools on an mcpkit service named =sprite= for driving *plain* sprites -- ephemeral, isolated Emacs daemons, typically one per git worktree, for running ERT or byte-compile checks without touching the user's main daemon (evaluating in the main daemon is /not/ isolated). No worktree, branch, or proxy route is created.

#+BEGIN_SRC emacs-lisp
(require 'sprite-mcp-tools) ;; registers the `sprite' service; started by mcpkit autostart
#+END_SRC

| Tool                   | Arguments                                   | Description                                                                                       |
|------------------------+---------------------------------------------+---------------------------------------------------------------------------------------------------|
| =sprite_start=         | =name=, =directory=?, =load_path=?, =require=?, =load=?, =timeout=? | Start a sprite; with =directory= set =default-directory= and prepend it (and =lisp/=) to =load-path=; then apply extra =load_path=, =require= and =load=. Starts an MCP service and registers a proxy route (=target_id=). |
| =sprite_run_tests=     | =name=, =main_features=?, =test_files=?, =load_path=?, =selector=?, =timeout=? | Run ERT in a sprite; returns success, passed/failed/skipped/total and failing tests. |
| =sprite_eval=          | =name=, =expression=, =timeout=?            | Evaluate Lisp in a sprite (full or short name); returns the printed result or the error text.    |
| =sprite_restart=       | =name=, =directory=?, =timeout=?            | Restart under the same name and re-apply the directory setup (restarted daemons are blank).      |
| =sprite_stop=          | =name=                                      | Stop the sprite and confirm it is no longer running.                                             |
| =sprite_list=          | none                                        | Running sprites: name, unique name, pid, uptime, directory.                                      |
| =sprite_cleanup_stale= | =dry_run=? (default true)                   | Report/delete state dirs that are empty or hold only a =DECOMMISSIONED= marker (not running).    |

Every tool returns a plist: =(:ok t ...)= on success, =(:ok nil :error MSG)= on failure; handlers never prompt or signal. The tools refuse to stop or evaluate in the current Emacs instance or its parent.

** Stop, don't decommission
The tools tear sprites down with =sprite-stop= only, never =sprite-decommission=. Decommissioning writes a permanent =DECOMMISSIONED= marker into the sprite's state directory; sprite indexes are reused after a sprite is gone, so a leftover marker later makes =sprite-create= refuse the reused name. Use =sprite_cleanup_stale= to find and remove such leftovers.

** How eval returns values
=sprite_eval= wraps the form in a =condition-case= that returns =(:ok PRINTED)= or =(:error MSG)=, so a =nil= result, a remote error and an unreachable sprite are distinguishable (=with-sprite= and =sprite-direct-eval-blocking= return plain =nil= for all of them). Evaluation runs with =default-directory= bound to the sprite's configured directory, because =emacsclient= rebinds it to the client's cwd on every call.

** Tests
=test/test-sprite-mcp-tools.el= mocks the sprite lifecycle. One integration test (real create/eval/restart/stop) runs only with =SPRITE_MCP_INTEGRATION=1=; run it in an isolated batch Emacs (own =HOME= and =sprite-instance-id=) since it spawns real daemons.
